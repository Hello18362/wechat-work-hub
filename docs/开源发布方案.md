## 二、核心问题：别人部署时，大模型怎么配

这是你这个项目能不能被别人跑起来的关键，我拆成三层讲。

### 2.1 你的 key 根本不会进仓库（先让你放心）

我完整扫了一遍代码和 git 历史：

- `.env` **从未被提交过**（`git log --all -- .env` 为空）
- 代码里**没有任何硬编码的 key**（全库正则扫 `sk-xxx` / `API_KEY=xxx`，命中 0 条）
- 密钥只从环境变量读，读取入口唯一：`core/config.py` 的 `load_settings()`
- `.gitignore` 里已经写了 `.env` 和 `.env.*`，只放行 `.env.example`

所以别人 clone 下来，拿到的是**一份空模板 `.env.example`**，里面写的是 `your_api_key_here`。他必须填自己的 key 才能用在线总结。

### 2.2 不填 key 会怎样：自动降级，不报错

这是项目原本就有的设计，也是最适合开源默认值的地方：

| 模式 | 配置 | 行为 | 成本 |
| --- | --- | --- | --- |
| `file_output`（默认兜底） | 不填任何 key | 把整理好的完整提示词写成 `runs/pending/xxx_content.md`，用户自己复制到任意 AI 对话框（网页版 DeepSeek / 豆包 / ChatGPT 都行） | 0 |
| `deepseek` / `openai` / `doubao` | 填 key + base_url + model | 直接调 API 出总结，全自动 | 按 token 计费，几毛钱一次 |

关键代码在 `summarizer/__init__.py`：检测到没 key 会打印一行警告「未检测到 API Key，自动回落到 file_output」，然后**继续跑完整条链路**，不会崩、不会卡。所以你不用担心别人没配好就来骂你，他至少能看到报告，只是总结那段是个提示。

### 2.3 支持哪些模型：只要是 OpenAI 兼容协议就行

代码实际请求的是 `POST {base_url}/chat/completions`，这是 OpenAI 的事实标准，所以国内外主流模型都能接。给你的 README 里我会放这张表：

| 服务 | `BASE_URL` | `MODEL` 示例 | 备注 |
| --- | --- | --- | --- |
| DeepSeek（项目默认） | `https://api.deepseek.com` | `deepseek-chat` | 最便宜，中文好，官方推荐 |
| 火山方舟 / 豆包 | `https://ark.cn-beijing.volces.com/api/v3` | 接入点 ID（`ep-xxxx`） | 豆包要先在方舟控制台创建推理接入点 |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | 长文本强 |
| 阿里通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 兼容模式 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` | |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | 需网络可达 |
| **Ollama（纯本地）** | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | key 随便填 `ollama`，见下方说明 |
| **LM Studio（纯本地）** | `http://127.0.0.1:1234/v1` | 加载的模型名 | key 随便填 |
| one-api / new-api 中转 | 你的中转地址 `/v1` | 中转里的模型名 | 适合多人共用一把 key |

给别人的 `.env` 模板（已在 `.env.example` 里，我会再补注释）：

```ini
# 三选一，任填一组即可；全空 = 走离线模式，不会报错
DEEPSEEK_API_KEY=你的key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_TEXT_MODEL=deepseek-chat
```

**Ollama 有个坑必须写进文档**：代码判断「有没有 key」来决定是否启用在线模式，而 Ollama 不需要 key。所以要显式填一个占位值（例如 `DEEPSEEK_API_KEY=ollama`），否则会被判定为不可用而回落离线。这个细节不写清楚，本地跑开源模型的人一定踩。

### 2.4 图片理解是另一套配置，要说实话

- 总结（文本）走上面那套；
- 图片理解走 `settings.yaml` 的 `vision.provider`，只有 `dummy`（返回占位符「图片」）和 `doubao`（火山视觉模型）两种；
- **DeepSeek 没有视觉能力**，所以如果你只用 DeepSeek，图片那块只能是占位符，或者额外再配一把豆包的 key 给视觉用。

这点我会在 README 里明确写成「能力矩阵」，避免别人以为配了 DeepSeek 就能识图。

### 2.5 还有个更大的依赖问题：数据源不在仓库里

这个必须提前说，否则别人 clone 下来 100% 跑不起来：

- 本项目**不含**微信解密工具。数据来自外部的 SIWX（stories-in-wx），它负责「取密钥 + 解密数据库」，本项目只读它输出的 SQLite。
- 也就是说，别人要能跑，需要：Windows + 微信 PC 版已登录 + 自己准备 SIWX + 在 `.env` 里填 `WX_DECRYPTED_DIR` 指向解密目录。
- README 里必须把这条放在「快速开始」最前面，写成前置条件，而不是脚注。

### 协议最终选择：PolyForm Noncommercial 1.0.0（可改 · 可用 · 不可商用）

第一版曾按「不许改」选了 PolyForm Strict，后来你改主意：**允许别人拿走改，但不许商用**。对应的正确协议是 **PolyForm Noncommercial 1.0.0**。

| 协议 | 能用 | 能改 | 能商用 | 能再分发 | 是否 OSI 开源 |
| --- | --- | --- | --- | --- | --- |
| MIT | 能 | 能 | **能** | 能 | 是 |
| AGPL-3.0 | 能 | 能（须开源） | **能** | 能 | 是 |
| PolyForm Strict | 能 | **不能** | 不能 | **不能** | 否 |
| **PolyForm Noncommercial 1.0.0（最终选定）** | **能** | **能** | **不能** | **能（须带协议与署名）** | **否** |

它同时给了两个许可：`Changes and New Works License`（可以改、可以基于它做新作品）和 `Distribution License`（可以把原版和修改版发出去），唯独把「商业目的」排除在允许范围外。

三点需要知道：

1. **不算 OSI 开源**，因为限制商用。GitHub 不会打 Open Source 标签。对个人使用者来说，实际自由度与 MIT 几乎一致。
2. **可以接受 Pull Request 了**。`CONTRIBUTING.md` 已改回「欢迎 PR」，只保留「不要提交真实聊天数据」这条硬规矩。
3. **署名靠 `Required Notice` 行保住**。`LICENSE` 开头写了 `Required Notice: Copyright 2026 Hello18362`，协议要求任何分发者必须把这行和协议原文一起带上。所以别人可以改、可以发，但作者署名跟着代码走——这正好解决了你担心的「改一改当成自己的项目」。

关于「开源项目是不是都能被拿走改」：**是，那正是开源的定义**。区别只在于 GPL / AGPL 要求改完也得开源。想要「可改但不可商用」，就得离开 OSI 开源阵营，用非商业协议——这是必然的取舍，不存在既算开源又能禁商用的选项。

## 五、发布形态：我建议「独立导出目录 + 干净历史」

### 为什么不直接用现有仓库

现有本地仓库只有 2 个 commit，但**第 2 个 commit 里已经写进了真实昵称**。公开仓库的历史是可被任何人 `git log -p` 翻出来的，删掉文件也没用，必须重建历史。

### 建议方案

新建一个**独立的发布目录** `D:\我的空间\product\wechat-work-hub-public\`，从开发目录按白名单导出经过脱敏的文件，在里面 `git init` 做首次提交，然后推到 GitHub 新仓库。

好处：

- 你正在用的开发目录**完全不动**（不会因为发布打断你本机使用）；
- 白名单导出天然防止「不小心把 runs/ 里真实报告提交上去」；
- 以后每次更新，跑一次导出脚本即可，两边不会串味。

导出脚本我会写成 `tools/export_public.py`，它做的事：复制白名单文件 → 替换 `groups.yaml` 为示例 → 删掉个人路径 → 扫一遍敏感词（真实群名、wxid、`C:/Users/0`）→ 有任何命中就中止导出并报告。

## 八、我额外建议加的两段 README 内容（别人最关心的）

**「它不能做什么」（限制声明）**——比吹功能更能建立信任：

- 只能读 Windows 微信 PC 版，且需要微信保持登录、电脑保持开机；微信不补采离线消息，关机期间的消息抓不到（这是微信机制决定的，不是 bug）
- 数据源依赖第三方解密工具 SIWX，本项目不分发、不内置
- 图片理解只有占位符和豆包视觉两种，DeepSeek 无视觉能力
- 没有任何云端同步，换台电脑要重新配

**「数据流向图」**——一句话说清隐私：

```
微信本地库 → SIWX 解密（本机） → 本项目读取（本机）
   → 语音/图片处理（本机） → 组装提示词
   → [可选] 发送给大模型 API（仅这一步出网，且内容由你决定）
   → 报告落盘（本机 runs/）
```

并注明：如果配的是 Ollama / LM Studio，则**全程不出网**。
