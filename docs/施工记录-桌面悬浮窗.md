## 一、现在能做什么

一个常驻桌面的玻璃小窗，显示置顶群今天要跟的活。

| 形态 | 尺寸 | 触发 |
| --- | --- | --- |
| 展开 | 540×780 | 默认 / 点一下玻璃球 |
| 玻璃球 | 68×68 | 点面板右上角「∨」 |
| 细条 | 6×168 | 吸附在边缘且鼠标离开 1.5 秒 |

交互：

- 拖到屏幕左/右边缘 24px 内自动吸附
- 吸附后鼠标离开 1.5 秒缩成细条，光标靠近 12px 内滑出
- 点卡片打开对应 HTML 报告
- 底部「已完成 N 条」点一下展开/收起已完成任务（最多 2 条）
- 右键菜单：打开最新报告 / 重新读取数据 / 收起成球 / 退出
- 位置与形态存 `%LOCALAPPDATA%\WeChatWorkHub\widget.json`，重启还原

数据每 3 秒检查一次 `cards.json` 的 mtime，变了就重画，不用重启小窗。

## 二、怎么用

**手动启动**（每次开机后想用就双击）：

```
启动悬浮窗.bat
```

它是 `pythonw` 后台拉起，不留黑框，成功会打印「启动成功」，失败会把报错留在窗口里。

**生成卡片数据**（第一次或想刷新时）：

```
python tools/make_daily_cards.py          # 只算置顶群（config/pins.yaml 或 groups.yaml 的 pinned）
python tools/make_daily_cards.py --all    # 所有有报告的群都算
```

置顶群这几天没有任务时，会自动退一步用全部有报告的群，不会让窗空着。

**开机自启 + 每天 08:00 自动出卡片**（可选，需要你自己跑一次）：

```
python tools/install_tasks.py            # 注册两个计划任务
python tools/install_tasks.py --status   # 看状态
python tools/install_tasks.py --remove   # 全部删掉
```

两个任务：
- `WeChatWorkHub\每日卡片` —— 每天 08:00 刷新解密数据 → 逐群出报告 → 写 cards.json
- `WeChatWorkHub\悬浮窗` —— 登录后延迟 30 秒打开小窗（等微信先起来）

## 三、和方案的三处差异（都是为达成方案的目的）

**1. 窗口骨架：`tkinter` → 纯 `ctypes` Win32 消息循环**

方案 4.1 写的是 `tkinter.Tk()` + `overrideredirect`，4.3 又要求 `UpdateLayeredWindow`。
这两件事互斥：tkinter 自己的绘制会和分层窗口抢像素，必然闪。
所以直接开一个 `WS_POPUP + WS_EX_LAYERED + WS_EX_TOOLWINDOW` 的窗口，
自己跑消息循环，内容就是一张 Pillow 画好的 RGBA 整图。
顺带的好处：不进 Alt+Tab、不进任务栏、没有第三方依赖。

**2. 玻璃：自己抓屏做磨砂，取代「三代系统降级」**

方案 4.4 想优先用 Win11 官方 Acrylic / Win10 的 `SetWindowCompositionAttribute`。
问题是：**DWM 不会给分层窗口做背景模糊**，这两条路和 4.3 的分层窗口天然打架，
一旦失效就只剩纯色底板。

现在的做法：用 `BitBlt`（不加 `CAPTUREBLT`，所以抓不到自己）取窗口背后的桌面 →
高斯模糊 → 压暗加冷调 → 贴成不透明底板。
好处是 Win10 / Win11 效果完全一致、不受驱动和系统版本影响、圆角与柔和投影都能拿到。

代价写在第六节：磨砂是「快照」，桌面内容变了最多 4 秒才跟上；拖动时按方案 4.5 主动关掉模糊。

`win32.py` 里的 `set_accent()` / `set_backdrop()` 两个原生 API 调用保留着，
以后想做「原生档」可以一行切换，只是当前不用。

**3. 卡片数量与已完成**

按你开工前定的：最多显示 6 张未完成（按紧急 > 高 > 重要 > 中 > 常规排序），
已完成的默认折叠，点开显示最多 2 张灰色紧凑卡。

## 六、已知限制

1. **我起不了常驻进程。** 我这边把 `pythonw` 拉起来，会话一结束就被回收（你之前踩过这个坑）。
   所以「双击 bat 之后窗口一直在」这步只能由你验证，机制和你已经在用的 `一键启动.bat` 一样。
2. **细条 6px 在亮壁纸上偏淡。** 你的桌面左侧图标多，6px 白条容易看丢。
   觉得找不到就改 `theme.py` 的 `SLIVER_W`（6 → 8），或者告诉我加个呼吸动画。
3. **磨砂是快照。** 桌面壁纸/后面窗口变了，最多 4 秒才更新一次；
   拖动过程中故意用实底（方案 4.5 就是这么要求的）。
4. **全屏游戏/播放器会把它盖住**，这是系统限制，没做全屏检测。
5. **鼠标穿透**：投影留白（几乎全透明）处点击会穿透到桌面，但卡片之间的细小间隙仍是窗口区域。

## 九、观感返工（2026-11-16 18:30，按用户反馈）

用户看完真机截图提了三条：**背景太实**、**卡片跟窗口的对比太强、在背景里显得突兀**、**动画不够流畅**。
逐条改了，全部是参数级改动，没动结构。

### 9.1 透明度：改成自适应

原来是固定一层 alpha 216 的压暗，等于给桌面盖了块深色板。现在：

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 压暗强度 | 固定 alpha 216 | **自适应 132 ~ 180**（按抓到的背景平均亮度算） |
| 背景饱和度 | 原样 | **去饱和 34%**（磨砂该是银灰调，不是彩色塑料） |
| 白色霜 | 无 | **alpha 12**（不然纯黑桌面上整块窗会"消失"） |
| 投影 | alpha 96 / 偏移 5 / 模糊 7 | **alpha 54 / 偏移 3 / 模糊 11**（更软，不像剪出来的） |
| 描边 | 46 / 顶棱 92 | **30 / 62** |

自适应规则：抓到的背景越亮，压得越深。白网页 → alpha 180（保证白字 9:1 对比度）；
彩色壁纸 → 中性；纯黑桌面 → 132（最透，但白字依然清晰）。

### 9.2 卡片：把二次凸起压下去

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 卡片填充 | 16 | **8** |
| 卡片描边 | 22 | **12** |
| 悬停填充 / 描边 | 26 / 46 | **20 / 30** |
| 分隔线 | 20 | **16** |

玻璃已经是一层半透明了，卡片再叠一层强对比就会出现"窗口里还有一层窗口"的突兀感。

### 9.3 动画：从 ~10 帧/次提到 17 帧/次

根因有两个，都不是"代码写得不够花"：

1. **逐像素跑 Python**。原来每帧对 alpha 通道调 `.point(lambda)`，一次 47 万次 Python 回调，
   单帧就要 30~50ms。改成 `Image.blend` + `ImageChops.lighter`（全 C 实现）后，
   **单帧 4.8~10ms**，稳定在 16ms 预算内。
2. **WM_TIMER 被系统合并**。系统默认时钟精度 15.6ms，`SetTimer(16)` 实际只能出 ~26ms 一帧，
   一次 260ms 动画只跑 10 帧。现在 `timeBeginPeriod(1)` + 帧间隔 8ms，
   实测 **17 帧/次（约 60fps）**，退出时 `timeEndPeriod` 还原。

缓动曲线也换成项目统一的 spring（`cubic-bezier(.22,1.2,.36,1)`，带一点点回弹），
不再是单调的 ease-out-cubic。

实测数据（`widget.log`，`WIDGET_DEBUG=1` 才有）：
```
anim done ball     frames 17  avg 4.8ms  max 10.5ms
anim done expanded frames 17  avg 9.5ms  max 12.3ms
```

## 十、第二轮返工（2026-11-16 18:40）：一个真 bug + 三个性能问题

用户反馈：**按住拖动时和静止时观感不一样**、**静止时光影模糊有偏移**、**缩放和动画有明显延迟卡顿**、**卡片再窄一点**。

### 10.1 模糊偏移：这是真 bug

`_refresh_backdrop()` 抓的是「面板区域」（去掉了 20px 投影留白），
但 `_frost()` 把这张图按「整个画布」的尺寸贴上去，于是整张模糊底被**平移了 20px**。
平时看不太出来，但卡片边缘与桌面对不上时会觉得"光影是偏的"。

修法：抓图直接抓整个窗口矩形 `(x, y, w, h)`，和画布 1:1 对齐。

### 10.2 拖动时观感突变：去掉"实底"档

原来按方案 4.5 的做法，按下就把磨砂切成不透明实底（alpha 232）防止掉帧。
问题是：**窗口本来就只在移动、不重绘**，那个实底完全没必要，
反而造成"按住就变成一块黑板、松手又变回玻璃"的跳变。

现在拖动全程保持磨砂，只是不重新取景（模糊图沿用按下前的快照）。
实测拖动期间没有重绘开销，所以也不卡。

### 10.3 动画延迟：真因是"动画开始前先阻塞了 300ms"

`_animate()` 在播第一帧之前要渲染两张整图（起点 + 终点），原来用的是 ss=2 超采样，
单张 150ms 左右 → **点一下要等 300ms 才开始动**，这就是"缩放放大有不小的延迟"。

三处一起改：

| 改动 | 效果 |
| --- | --- |
| 起止图改用 1x 画布 | 单张 150ms → **10ms** |
| 画布倍数 2x → 1x，圆角改用**遮罩羽化 0.55px** + 「外环减内环」的抗锯齿细边 | 观感等于 2x，成本降到 1/3 |
| 磨砂压暗链路全部挪到半分辨率做（三次全画布合成 → 三次半画布 blend + 一次放大） | 首帧 182ms → **62ms** |
| 动画结束不再强制重抓背景 + 重绘 | 收尾不再顿一下 |

实测（`WIDGET_DEBUG=1`）：
```
anim start expanded -> ball  prep 14ms
anim done  ball              frames 17  avg 4.9ms  max 8.1ms
anim start ball -> expanded  prep 12ms
anim done  expanded          frames 16  avg 10.3ms max 15.6ms
```
**动画准备 12~14ms，单帧 5~11ms，一次 260ms 动画 16~17 帧。**

### 10.4 卡片收窄

`PAD_X` 26 → **34**，卡片宽度 488 → **472**，两侧留白变宽，视觉上不再顶到面板边。

### 10.5 留给下一轮的

- 静态重绘（换背景/刷新数据）首帧仍要 62ms，如果之后觉得"背景一变就卡一下"，
  可以把它拆到空闲时刻做。
- 卡片底色在**深色桌面**上看起来偏亮（白色 8/255 叠在近黑底上相对更明显）。
  如果觉得扎眼，改 `theme.py` 的 `CARD_FILL` 8 → 6。

## 十一、第三轮：黄金比例 + 逐像素压暗 + 自动让位（2026-11-16 18:45）

用户要求：透明再透一点、卡片再淡一点、动画再快一点、打开报告后自动缩小、卡片比例用黄金比例。

### 11.1 面板改成黄金比例

`PANEL_W` 540 → **482**，`482 : 780 = 0.618`（严格黄金比）。
卡片宽度跟着从 472 收到 **414**，观感上不再像一条条扁条。
所有布局都是从 `PANEL_W/PANEL_H` 推出来的，改一个常量就够，不用逐个挪。

### 11.2 均匀压暗 → 逐像素自适应压暗（关键改动）

之前是「先算整块背景的平均亮度，再定一个统一 alpha」。这在**面板一半压在白色网页、一半压在深色壁纸**时必然出错：
白字在半边看得清、另半边糊掉。用户截图里就是这样。

现在是逐像素：把模糊后的背景转灰度，用一条 LUT 映射成「该压多深」的遮罩，
再 `Image.composite` 一次性合成。亮的地方压到 alpha 238，暗的地方只压 86。

实测同一张图上下两半：
```
压在白色网页上：面板色 (52,53,55)，白字对比度 12.3:1
压在深色壁纸上：面板色 (32,33,36)，白字对比度 16.1:1
```
代价：一次 `convert("L")` + `point(LUT)` + `composite`，都在半分辨率上做，几毫秒。

| --- | --- | --- |
| 卡片填充 | 8 | **5** |
| 卡片描边 | 12 | **8** |
| 悬停填充 / 描边 | 20 / 30 | **16 / 22** |
| 动画时长 | 260ms | **200ms**（项目区间下限） |
| 三级灰文字 | 114 | **128**（浅色玻璃上不再发灰） |

## 十二、修复「收起时出现黑框」（2026-11-16 18:55）

用户反馈：球形态外面套着一块黑色方块。

### 根因：动画帧的 alpha 取了 max

收起动画每帧是「起点图（面板）」和「终点图（球）」各缩放到当前尺寸后混合。
当初为了防止中途整窗变透明，alpha 用的是 `max(fi.alpha, ti.alpha)`：

```python
canvas.putalpha(ImageChops.lighter(fi.getchannel("A"), ti.getchannel("A")))
```

问题是面板的 alpha 在整个圆角矩形内都是 255。于是**面板缩到 96px 的过程中，
那几帧的 alpha 仍然是 255** —— 屏幕上就是一块缩小的、不透明的黑色圆角方块，
也就是用户看到的黑框。球本身在第 3 节已经验证过 alpha 正确（圆外全 0），
所以问题不在球的绘制，而在过渡帧。

### 改法

1. **alpha 分开给曲线**：起点快速退场 `(1-e)^2`，终点提前登场 `e^0.5`，取两者较大值。
   这样面板的不透明度几十毫秒内就掉下去，球同时立起来，不会有"缩小的黑板"。
2. **退场侧随进度变糊**（`GaussianBlur(0.4 + 3.2e)`）：面板文字在缩小时化开，
   读不出内容，视觉上是"失焦转移"而不是两个画面互相透。
   模糊作用在**已缩放的小图**上，成本可以忽略。

验证方式：动画过程中逐帧抓屏，检查窗口四角像素——全部是桌面透过来的颜色，
不再出现近黑值；静止后四角同样是桌面色。

### 顺带加的调试开关

`WIDGET_DUMP=1` 会把每一帧实际画出去的图存到
`%LOCALAPPDATA%\WeChatWorkHub\paint.png`。以后再有"画面对不上"的问题，
先把这张图捞出来看 alpha，比盯着屏幕猜快得多。

## 十四、严重 bug：面板越用越黑、卡片发虚、滚动背景异常（2026-11-17 23:25）

用户反馈三件事：**改完就变成不透明的深黑块**、**卡片很模糊**、**滚动时背景有 bug**。
看着像三个问题，其实是**同一个根因**。

### 14.1 根因：BitBlt 把我们自己的窗口也抓进去了

`_refresh_backdrop()` 用 `BitBlt` 抓窗口背后的桌面，原本假设「不加 `CAPTUREBLT` 就不会抓到自己」。
实测证明这个假设是错的——抓出来的图里就是自己的面板（拿球形态试，抓到的就是那个球）。

于是形成了滚雪球：

```
抓一次 = 自己的半透明面板 → 模糊 + 再压暗 → 画到屏幕上
1.5 秒后再抓 = 刚才那张更暗的面板 → 再压暗 → 更黑
…… 几轮之后就是一块不透明的深黑方块
```

这同时解释了另外两个现象：
- **卡片发虚**：背景里叠着「上一帧自己的卡片」的模糊影子，看起来像卡片重影。
- **滚动背景异常**：滚动重绘时用的正是这张被污染的背景。

为什么"我改的时候挺好、改完就变黑"：每次改完重启，首帧用的是干净背景，
之后每 1.5 秒一轮，肉眼看到的就是「先是好的，几秒后变黑」。

### 14.2 修法

1. **抓屏前必须让窗口不可见**：`hide()` → `capture()` → `show()` + 重新置顶。
2. **取消空闲定时重抓**：它是污染源，而且每次重抓都要闪一下。现在只在
   ①启动（窗口还没显示，天然干净）②拖动结束（hide/show 一次）③展开到更大尺寸时抓。
3. **展开时用预热好的背景**：球形态空闲时先把展开态的玻璃生成好（约 70ms，发生在空闲，
   用户看不到），并把展开区域要用的背景一起抓好。这样点球展开不用现抓 —— 也就不会抓到自己。

### 14.3 顺带解决的性能回退

上一版为了让展开拿到正确的背景，在动画开始前 hide + 抓 + 重建整块玻璃，
准备时间从 12ms 涨到 **111ms**（点下去明显顿一下）。本次：

| 改动 | 效果 |
| --- | --- |
| 球形态空闲时预热展开态玻璃 | 展开 prep **111ms → 19ms** |
| 遮罩 / 描边环按尺寸缓存（与背景无关） | 省掉每次重建的两张遮罩 + 两个环 |
| 展开时不再 hide 窗口 | 没有闪，也省掉一次 hide/show |

### 14.4 验证

- 连续 16 秒每隔 4 秒采样面板同一块区域：**116.1 → 116.1 → 116.1 → 116.1 → 116.1**，亮度不再漂移。
- 抓屏自测：hide 之后抓到的图里不再有自己的窗口。
- 展开 prep 19ms，动画 12~17 帧。

## 十五、卡片对比度 + 完成功能（Mac 坞式收纳）（2026-11-17 23:40）

### 15.1 对比度

卡片填充 13 → **22**，描边 20 → **34**，悬停 34 / 52。玻璃本身很透，卡片再淡就分不出层级了。

### 15.2 完成按钮

每张卡左侧加一个 18px 的圆钮（文字整体右移 27px）：
默认是 1.3px 白色描边圆；悬停时变成橙色实心 + 白色对勾。点一下 = 标记完成。

### 15.3 完成后收进右上角

完成的任务从列表里消失，卡片缩成一张 **34×22 的迷你卡**，收在头部右侧（更新时间和收起按钮之间），
最多放 6 张。点迷你卡 = 恢复成待办，回到列表。

这就是用户要的「Mac 程序坞最小化」的效果：

- 点击完成时，先把**当前卡片从上一帧画面里裁下来**（`self._last_img.crop`），
  然后立刻重排列表，再让这张裁下来的卡片从原位置缩放飞到迷你卡的位置（300ms，带一点上抛弧线）。
- 关键技术点：**飞行的计时起点不能设在点击那一刻**。点击后消息队列里还压着一堆
  `WM_MOUSEMOVE`，等第一帧真正跑起来时动画已经过半（实测 t=0.51），看起来就像"没有动画"。
  改成 `t0 = None`，在 `_fly_frame` 第一帧才赋值。
- 透明度在 e>0.78 之后才开始降，太早淡会像"卡片没飞过去就消失了"。

### 15.4 完成状态存哪儿

**不改 cards.json**（它是调度任务写的，改了会被覆盖）。单独存
`%LOCALAPPDATA%\WeChatWorkHub\done.json`，键是「群名|标题」。
这样调度任务重写数据、报告重新生成，完成状态都还在。

底部那行从「已完成 N 条 ⌄」（可展开）改成「已完成 N 条 · 收在右上角」的纯文字——
已完成都收到右上角了，原来那个展开面板就没意义了。
