## 一、要做什么

一个常驻桌面的**悬浮小窗**，展示「今天置顶群的待办卡片」。

每张卡片显示：**群名 / 源（发起人 + 时间）/ 人（指定对象）/ 时（截止）/ 优先级**。

两种形态：

| 形态 | 尺寸 | 说明 |
| --- | --- | --- |
| **展开态** | 约 540 × 780 | 竖排卡片，点击任意卡片直接打开对应报告 |
| **收起态** | 约 68 × 68 玻璃球 | 球内显示今日待办数；双击球打开最新报告 |

交互：

- 拖到屏幕左/右边缘 24px 内 → 自动吸附
- 吸附后鼠标离开 1.5 秒 → 缩成细条（参考 QQ 边缘隐藏）
- 鼠标靠近细条 → 滑出展开
- 位置记忆（存 JSON，下次启动还原）

## 四、技术方案

### 4.1 窗口骨架

- `tkinter.Tk()` + `overrideredirect(True)`（无边框）
- `attributes('-topmost', True)`（置顶）
- 用 `WS_EX_TOOLWINDOW` 让它不出现在 Alt+Tab 里
- 位置写入 `%LOCALAPPDATA%\WeChatWorkHub\widget.json`

**已知坑**：按 `Win+D` 显示桌面时置顶窗会被最小化，需要监听后 `SetWindowPos` 重新置顶。

### 4.2 动画与吸边

- 帧循环用 `after(16)`（约 60fps），缓动函数 `1 - (1-t)^3`
- 拖拽：`ButtonPress` 记起点 → `B1-Motion` 每帧 `geometry()` 移动
- 吸边：松手时判断到屏幕边缘距离 < 24px → 动画贴边
- 边缘隐藏：`after(100)` 轮询 `GetCursorPos`，判断光标与细条的距离

**参数需要真机反复试**（这是"手感"部分，无法在沙箱里验证）：

| 参数 | 起始值 | 说明 |
| --- | --- | --- |
| 吸边触发距离 | 24px | 太小难吸，太大误吸 |
| 收起动画时长 | 260ms | 参考项目统一动效 200–420ms |
| 自动隐藏延迟 | 1500ms | 鼠标离开多久后缩成细条 |
| 细条宽度 | 6px | 太窄不好点，太宽碍事 |
| 滑出触发距离 | 12px | 光标距细条多少像素触发展开 |

### 4.3 玻璃渲染（**最不确定的部分**）

**核心思路**：窗口用**分层窗口**（`UpdateLayeredWindow`），内容是自己用 Pillow 画好的**带透明度整图**；磨砂感由系统的背景模糊提供。

分三层：

1. **系统层**：让窗口背后的桌面内容变模糊（见 4.4 的三代降级）
2. **玻璃层**：Pillow 里画——
   - 圆角矩形遮罩（radius 24）
   - 暗色底 `rgba(16,16,18,150)`（保证白字可读）
   - 顶部白色高光 `rgba(255,255,255,16)`
   - 细亮边 `rgba(255,255,255,120)` 2px
   - 外投影（在窗口范围内留 20px 边距画高斯模糊的黑影）
3. **内容层**：卡片、文字、优先级 chip

**为什么不用普通 tkinter 绘制**：普通绘制无法做逐像素半透明，圆角只能靠 `SetWindowRgn` 裁剪，边缘有锯齿、也做不出柔和投影。

**重绘时机**（错一处就闪/糊/卡）：

| 场景 | 是否重画整图 |
| --- | --- |
| 拖动位置 | ❌ 只移动窗口，不重画（关键：这里重画会卡） |
| 展开/收起动画 | ✅ 每帧尺寸变，必须重画 |
| 数据刷新 | ✅ |
| 鼠标悬停高亮 | ✅ 只重画那一张卡片区域（可选优化） |

### 4.4 模糊的三代降级（Win10 / Win11 都要能用）

```
build >= 22621 (Win11 22H2+)
  → DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE=38, DWMSBT_TRANSIENTWINDOW)
     官方 API，最稳、效果最好
  失败 ↓

build >= 17134 (Win10 1803+ / Win11 早期)
  → SetWindowCompositionAttribute(
        AccentPolicy{ AccentState=ACCENT_ENABLE_ACRYLICBLURBEHIND(4) 或 BLURBEHIND(3) })
     未公开接口，能用但不保证
  失败 ↓

兜底
  → 纯不透明深色面板（保留圆角 + 投影）
     玻璃感打折，但绝不崩
```

**实测结论（本机 Win10 19045）**：`SetWindowCompositionAttribute`、`SetWindowRgn`、
`UpdateLayeredWindow`、`SetLayeredWindowAttributes`、`DwmSetWindowAttribute`、
`CreateRoundRectRgn` **全部存在**，可调用。

**圆角也要分支**：Win11 用 `DWMWA_WINDOW_CORNER_PREFERENCE`；Win10 用 `SetWindowRgn` +
`CreateRoundRectRgn`（或直接靠分层窗口的 alpha，边缘更平滑）。

### 4.5 拖动时关模糊

拖动期间逐帧改窗口位置会让模糊重算，容易掉帧。处理：

- `ButtonPress` → `SetWindowCompositionAttribute(ACCENT_DISABLED)`，同时切成不透明底
- `ButtonRelease` → 恢复模糊档位

视觉上用户几乎察觉不到，但拖动会明显顺滑。**这个处理已验证有效，务必保留。**

### 4.6 DPI

- 进程启动先 `SetProcessDpiAwareness(2)`（per-monitor DPI aware）
- 分层窗口的位图必须按**物理像素**给，否则字被二次缩放变糊
- 鼠标坐标是逻辑像素，贴边判定前乘 `scale = GetDpiForWindow()/96`
- 换显示器时重新取 DPI 并重画
- 多显示器且缩放不同时，按窗口所在显示器取

## 五、数据契约

小窗**只负责显示**，数据由调度任务写文件。

`%LOCALAPPDATA%\WeChatWorkHub\cards.json`：

```json
{
  "generated_at": "2026-11-15 08:00:12",
  "groups": 6,
  "total_messages": 86,
  "cards": [
    {
      "group": "示例 · 项目协作群",
      "title": "完成 v0.9 回归测试并输出报告",
      "priority": "紧急",
      "source": "张经理 09:13",
      "owner": "李主管",
      "due": "周四 18:00",
      "done": false,
      "report": "2026-11-14_示例·项目协作群.html"
    }
  ]
}
```

**刷新机制**：小窗每 3 秒检查 `cards.json` 的 mtime，变了就重新读并重画。
**不需要重启小窗。**

字段来源：`extract_task_cards()` 已能给出 `title / priority / owner / due / source / done`；
`report` 由生成报告时的文件名填入。

## 六、每日调度

```
每天 08:00（Windows 计划任务「登录时触发」或「每天定时」）
  → python "…\siwx\run.py" auto          刷新微信解密数据
  → python main.py --group <置顶群> --date yesterday -f both   逐个生成报告
  → python tools\make_daily_cards.py     抽卡片 + 写 cards.json
  → 小窗自动刷新
```

群范围：**只跑控制台里点了图钉置顶的群**（`config/pins.yaml`）。

失败兜底：
- 某个群失败 → 跳过并记日志，其余继续
- 全部失败 → 保留上一次的 cards.json，小窗顶部显示「数据为 N 小时前」

## 九、风险清单

| 风险 | 等级 | 兜底 |
| --- | --- | --- |
| 模糊接口在新系统/新驱动上失效 | **高**（不可控） | 三代降级，最差退回纯色面板 |
| 圆角锯齿（Win10 无原生圆角） | 中 | 用分层窗口 alpha 代替 SetWindowRgn |

| 多显示器不同缩放 | 中 | 按窗口所在显示器取 DPI |
| 全屏游戏/播放器把窗盖住 | 低（系统限制） | 检测全屏时自动隐藏 |
| 常驻内存/CPU | 低 | 只在数据变化时重画，光标轮询 100ms |
